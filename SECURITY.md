# Security status

Это исследовательский прототип, не готовый публичный сервис и не подтверждённая защищённая среда.

## До первого публичного доступа

- Подтвердить фактическую работу закреплённого образа и bootstrap.
- Создать администратора закрыто, затем включить регистрацию с default role user.
- Настроить HTTPS, cookie security, допустимый Origin и доверенные proxy.
- Проверить всю штатную поверхность Open WebUI, а не только добавленные endpoints.
- Реализовать и проверить rate limits, учёт ресурсов и квоты до включения публичного provisioning.
- Не передавать Docker socket, управляющие ключи или произвольный RPC proxy пользовательским агентам.
- Не доверять user-id заголовку/полю body без проверенной серверной identity.
- Проверить реальные отрицательные сценарии для двух пользователей.

## Текущие границы

Новый API принимает только явную human-session Bearer-аутентификацию, опираясь на штатную проверку Open WebUI. Это осознанный отказ от его cookie fallback только в новом API, а не исправление всех возможных CSRF-рисков upstream. XSS в том же origin может угрожать токену в localStorage: не считать его невидимым для JavaScript.

Сохранённые инструкции — недоверенные пользовательские данные, а не доверенная системная policy. Их длина не является проверкой безопасности содержимого.

Docker-supervisor в проекте ещё не подключён, поэтому код сейчас не предоставляет права управления контейнерами. Compose не монтирует Docker socket. Проверки образа и `main.py` обеспечивают воспроизводимость выбранной интеграции, но не доказывают отсутствие уязвимостей образа.

Не прикладывайте реальные ключи, `.env`, содержимое пользовательских баз или непроверенные логи к GitHub issues. Результаты тестов и минимальные обезличенные воспроизведения безопаснее полного дампа.
