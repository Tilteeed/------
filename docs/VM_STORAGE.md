# Хранилище данных агентов на ВМ

> **Только текущая лабораторная ВМ пользователя. Конечный стенд будет на другой машине.** UUID, устройства, пути и размеры ниже — свидетельства этой ВМ, не универсальная конфигурация и не значения для хардкода. Для новой машины нужно определить и задать собственные параметры: см. `docs/DEPLOYMENT_CONFIG.md`.

## Актуальное состояние — предоставленные пользователем свидетельства

Пользователь самостоятельно подготовил новый диск и XFS для данных агентов. Это текущая основа проектирования storage backend. Подготовку корневого ext4 больше не считать выбранным следующим шагом.

| Параметр | Значение |
| --- | --- |
| Диск | `/dev/sdb`, 50 GiB по выводу fdisk |
| Раздел | `/dev/sdb1` |
| Файловая система | `xfs` |
| Метка | `AGENT_DATA` |
| UUID ФС | `f187448b-d3e6-4838-b7c1-893b34886010` |
| Точка монтирования | `/srv/agent-data` |
| Project quota accounting | `ON` по `xfs_quota -x -c 'state -p'` |
| Project quota enforcement | `ON` по той же команде |
| Свободное место в присланном снимке | `49G`, общий размер ФС `50G` по `df -hT` |

UUID и точка монтирования являются ожидаемой идентичностью только этой лабораторной ВМ; имя устройства может измениться после перестановки дисков. На другой машине ожидаемая идентичность задаётся её deployment-профилем. Размеры и свободное место — снимок, не постоянно гарантированный ресурс.

## Постоянное монтирование

Пользователь добавил в `/etc/fstab` текущей ВМ следующую запись. Это свидетельство выполненной настройки, не готовая строка для другой машины:

```fstab
UUID=f187448b-d3e6-4838-b7c1-893b34886010 /srv/agent-data xfs defaults,prjquota,nofail 0 0
```

Предоставлен результат `findmnt --verify --verbose`: 0 parse errors, 0 errors, 1 warning. Предупреждение относится к отсутствующему носителю `/media/cdrom0`, а не к XFS. Проверка реального монтирования после перезагрузки не предоставлена; успешная проверка fstab не подменяет её.

## Что подтверждено и что ещё нет

- Подтверждены создание и текущее монтирование XFS, включённые на уровне ФС accounting/enforcement project quotas и запись fstab.
- Назначение отдельного project ID каталогу агента, hard limit 10–15 ГБ и фактический отказ записи при превышении пока не показаны. Готовность механизма ФС не равна принятой квоте каждого экземпляра.
- Связывание будущих state/workspace/credentials с этим хранилищем не выполнялось помощником. Миграция данных существующих контейнеров и перенос DockerRootDir не подтверждены.
- Ранее исследованный `/dev/sda1` остаётся исторической диагностикой корневого ext4. Старый `lab/storage/inspect_ext4.py` исследует DockerRootDir, а не произвольный новый том, поэтому его нельзя выдавать за проверку `/srv/agent-data`.
- Квота личных данных сама по себе не ограничивает writable layer и внешние логи Docker. Полный охват записи требует отдельного профиля и испытаний.

## Обязательные проверки будущего storage backend

1. До любой записи/создания экземпляра проверить фактический mount/UUID/тип ФС по deployment-профилю конкретной машины. Для этой лабораторной ВМ ожидаются `/srv/agent-data`, XFS и UUID из таблицы; для конечного стенда значения определяются заново. Проверки одного существования каталога недостаточно; путь не должен оказаться обычным каталогом на `/`.
2. Проверить актуальное состояние quota accounting/enforcement и соответствие назначенного project ID утверждённому экземпляру/владельцу.
3. При отсутствии ожидаемого mount, другой идентичности или неработающих квот — отказ до создания/записи. Не делать автоматический fallback на корневой ext4. Наличие `nofail` в fstab не является разрешением supervisor продолжать без тома.
4. После настройки отдельного проекта доказать hard limit контролируемым тестом, а также сохранение конфигурации/данных после согласованных перезапусков.
5. Режимы retain/purge и повторное подключение данных остаются owner-scoped; project ID не освобождается, пока его данные сохранены.

Это требования к будущей реализации, не уже добавленные guard checks.

## Граница разрешений

Подготовку диска и fstab выполнил пользователь. Помощник только сохранил предоставленные сведения. Это не разрешает повторное форматирование, remount, изменение fstab, миграцию, назначение новых квот или удаление данных. Следующие изменяющие хранилище операции согласовываются отдельно.
