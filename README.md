# Персональные агенты · дополнение к Open WebUI

Проект практической части диплома: локальные исходники → GitHub после согласования → clone/build на отдельной ВМ. Публикация и удалённое развёртывание автоматически не выполняются.

## Назначение

Открытая регистрация и выдача персональных экземпляров OpenClaw в контейнерах на отдельной ВМ. Пользователь получает доступ к собственному агенту, данным и разрешённым настройкам, но не к Docker API или обязательным политикам платформы.

## Первая веб-часть

Основа — закреплённый Open WebUI v0.12.5-slim. Его регистрацию, вход и чат не переписываем. Дополнение добавляет same-origin страницу `/agent` и API подготовленных настроек.

В коде реализованы owner-scoped SQLite, ревизии и конфликт 409, ограничение пользовательских полей, явная human-session Bearer-аутентификация через upstream dependency, Origin/JSON/body-size проверки, небольшой журнал без текста инструкций. Локальные HTTP-тесты внедряют тестовые identities только в `tests/`: реальная аутентификация Open WebUI ими не проверяется.

**Веб-базис запущен на ВМ и принят пользователем:** подтверждены регистрация, вход/выход, сохранение после перезапуска, разделение данных двух аккаунтов и отказ API без токена. Отдельный лабораторный OpenClaw без LLM также запущен и проверен; результаты и image ID — в `docs/ROADMAP.md`. Это пользовательская ручная приёмка, не завершённый аудит безопасности. Проект не готов к публичному интернет-хостингу.

Добавлена сквозная связка кабинета с отдельным host-supervisor: приватный Unix socket, долговечные операции/резервы, метрики хоста, подготовка XFS project quota и Docker executor. Включается отдельно через `compose.supervisor.yaml`; базовый Compose сохраняет web-only режим и честный 503 без runtime. Инструкция запуска — `docs/SUPERVISOR_RUN.md`.

Локально выполнен сквозной HTTP/SQLite smoke создания, остановки, повторного запуска, удаления с сохранением данных и разделения владельцев; Docker/XFS/метрики в нём явно имитированы. Реальный новый runtime на XFS/Docker ВМ ещё не принят. LLM, чат с Gateway и Telegram не подключены. Инструкции используются при первоначальном создании; последующие сохранения остаются черновиком. Порог 50% сохранён как правило проекта.

На основной Windows-системе новые зависимости не устанавливались. Основная сборка и тесты предусмотрены внутри Docker на ВМ.

## Запуск имеющихся тестов

Если FastAPI и httpx уже доступны, из корня папки:

```console
python -m unittest discover -s tests -v
node --test tests/ui-state.test.mjs
```

Без внешних Python-библиотек можно отдельно запускать `test_policy.py`, `test_store.py`, `test_init_env.py` и `test_integration_patch.py` через `python -m unittest discover -s tests -p <filename> -v`. Штатно все Python- и JS-тесты входят в стадии Dockerfile на ВМ. Не устанавливайте пакеты глобально ради проверки.

## Структура

- `control_plane/` — политики, SQLite, API и интеграция с Open WebUI.
- `web/agent/` — кабинет с управлением своим экземпляром; штатный чат сохраняется.
- `supervisor/` — привилегированный Linux host-service, XFS volumes, Docker Engine client и политики.
- `compose.supervisor.yaml` — opt-in IPC bridge без Docker socket в вебе.
- `scripts/configure_supervisor.py`, `docs/SUPERVISOR_RUN.md` — явная настройка и запуск на ВМ.
- `scripts/smoke_runtime.py` — один переносимый сквозной сценарий с fake Docker/XFS, не приёмка ВМ.
- `scripts/` — генерация локальной конфигурации и проверяемый upstream patch.
- `tests/` — исполняемые проверки.
- `Dockerfile`, `compose.yaml` — сборка и запуск веба без Docker socket.
- `upstream.lock.json` — версии, commit и digest.
- `docs/requirements.md`, `docs/architecture.md`, `docs/deployment.md` — требования, архитектура, развёртывание.

## Доставка на ВМ

Перед переносом на другую машину: [руководство по адаптации стенда](docs/DEPLOYMENT_CONFIG.md). UUID, устройства, пути и ресурсы из `docs/VM_STORAGE.md` относятся только к лабораторной ВМ; политика 50% не требует изменения из-за смены машины.

Команды для подготовленной Linux-ВМ с Docker/Compose и Python 3.12+:

```bash
git clone <REPOSITORY_URL> agent-platform
cd agent-platform
python3 scripts/init_env.py
docker compose config --quiet
docker compose build
docker compose up -d
```

По умолчанию публикуется только `127.0.0.1:3000` ВМ: первый доступ через SSH-туннель. Создайте администратора закрыто, затем включите открытую регистрацию с ролью `user` в штатных Admin Settings. Подробности — `docs/deployment.md`.

**Не коммитьте `.env`, токены, базы и volumes.** Скрипт генерирует местный случайный ключ, не печатает его и не перезаписывает существующую конфигурацию.

## Границы имеющихся проверок

`require_owner` сам не устанавливает личность. API получает пользователя от штатной upstream dependency, а хранилище ограничивает запросы этим владельцем. Передача пользовательского `owner_id` запрещена. Фактический вход Open WebUI на ВМ подтверждён пользователем; локальные unit-тесты отдельно этого не доказывают.

Входные ограничения имени и инструкций — технические границы формы, а не детектор промпт-инъекций. Объект хранения пока один документ подготовленных настроек на пользователя. Для будущего runtime уже принято ограничение: один не удалённый экземпляр на пользователя, включая остановленный; существование черновика не означает создание такого экземпляра.

Нет заглушки, которая выдавала бы фиктивное `running` или ответы LLM.

Брендинг и условия лицензии Open WebUI сохраняются: см. `THIRD_PARTY_NOTICES.md`. Лицензию собственного кода следует выбрать отдельно перед распространением.
